# 架构决策记录

新增或实质改变模块边界、数据存储策略、权限隔离模型、对外接口契约、部署方式或关键依赖选型的决策时，在 `docs/adr/` 中新增 ADR。普通修复、局部重构和不改变既有边界的字段增补不必创建。仓库已有其他 ADR 目录时沿用现有位置。

写作前先阅读相关代码与已有 ADR，区分：已实现行为、准备采用的方案、尚未验证的假设。不要编造备选方案或测试结果。

文件命名：`NNNN-short-title.md`。内容包含：

- Status：Proposed / Accepted / Superseded。按实际采纳情况填写；Accepted 表示方案已采纳，不表示代码已完成。未实现的方案明确标注，尚无实现时 Code 写预计落点并注明。
- Date
- Code：相关实现路径与关键符号
- Context：具体问题、触发场景和约束
- Decision：选择的方案、行为与边界，以及关键理由
- Consequences：收益、代价、限制和兼容性影响

保持简短具体，不堆砌背景。需要解释非显然设计约束时，代码注释引用相关 ADR，避免重复长篇设计说明。

同步更新 `docs/adr/README.md` 索引。改变已有决策方向时，新增 ADR 并标记替代关系；小范围补充可追加带日期的 Addendum，保留原有理由。
