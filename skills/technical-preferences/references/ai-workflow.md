# AI 协同开发流程

适用于从零规划项目、拆分复杂模块边界，或按规格驱动、测试驱动与持续回归方式推进人机协同开发的场景。日常单文件脚本或局部小修不强制套用全部流程，按任务复杂度裁剪使用；仓库已有成熟流程时优先沿用仓库约定。

## 1. 架构拆解：公理设计与模块正交

动工前先收敛需求与模块边界，再进入编码：

- **FR-DP 映射**：将整体目标拆解为明确的功能需求（FR），尽量让每个 FR 对应独立的设计参数/模块（DP），使模块正交、低耦合、高内聚，修改单一需求只影响对应模块。
- **确定职责与接口**：先明确模块依赖关系、核心数据结构与边界接口，再交由 AI 填充实现；涉及重要边界、存储或接口选型变更时，配合 [架构决策记录](adr.md) 留存决策。

## 2. 规格与验证：BDD 场景与 TDD 循环

以可执行测试作为需求共识、AI 实现约束与长期回归安全网：

- **BDD 验收场景（按需）**：面对业务规则复杂或需跨角色确认的功能，用 Gherkin（`Given-When-Then`）描述外部可观察行为，避免混入实现细节；Python 项目可用 `pytest-bdd` 或 `behave` 将场景绑定为可执行测试。
- **TDD 短迭代**：
  1. **先定测试**：根据场景或模块规格编写/更新失败测试（单元测试与集成测试），明确输入输出与边界条件。
  2. **最小实现**：让 AI 编写刚好通过全部测试的实现代码。
  3. **绿灯重构**：测试通过后，再要求 AI 消除重复、优化结构，并复跑测试确认仍全绿。
- **回归与性质测试**：将历史缺陷用例长期保留在回归测试集中，防止重构引入回归；数值计算或边界复杂的核心算法，可补充性质测试（如 Python 的 `hypothesis`）或性能基准测试（如 `pytest-benchmark`）。

## 3. 代码设计：AI 友好的函数式原则

降低隐含状态与上下文复杂度，使 AI 生成的代码更易验证与维护：

- **纯函数优先**：核心业务与计算逻辑尽量写成纯函数——相同输入总产生相同输出，不依赖全局状态，不触发隐蔽副作用。
- **I/O 与核心逻辑隔离**：文件读写、网络请求、硬件控制等副作用收敛在边界层或接口层；核心逻辑仅接收结构化输入并返回结果或待执行指令，便于脱离外部环境独立单测。
- **小函数可组合**：将复杂流程拆分为单一职责的小函数，先独立实现并测试，再组合调用。
- **不可变数据与显式类型**：优先使用不可变数据结构，减少共享可变状态；补充类型注解帮助人机双方明确数据契约。

## 4. 版本控制与自审

用细粒度版本记录控制 AI 改动的变更半径：

- **分支策略**：优先沿用仓库已有分支模型；独立或新建项目可根据协作规模采用主干开发（`main` + 短生命周期 `feature/*` / `fix/*`）或 Git Flow（`main` 发布、 `develop` 集成、`feature/*` 与 `hotfix/*` 隔离开发）。
- **小步原子提交**：每次提交聚焦单一主题（如一个测试及其对应实现、或一处独立修复），避免把无关改动混入同一提交，方便审查与回滚。
- **提交信息与自审**：遵循 Conventional Commits（如 `feat:`、`fix:`）概括改动内容与意图；合并前通过 diff 或 PR 界面自审 AI 生成的变更，把自审作为质量门禁。

## 5. 持续验证与文档同步

- **本地快速反馈 + CI 全量防回归**：每次生成或修改代码后本地运行相关测试；在 CI（如 GitHub Actions / GitLab CI）中自动执行全量测试、覆盖率检查（如 `pytest-cov`）、格式化与静态检查、类型检查及文档构建，确保改动不破坏既有功能。需要跨环境一致运行时，配合容器化（`Dockerfile`）固定运行环境。
- **代码即文档**：公开模块、类和函数同步补充清晰的 docstring（按仓库约定或使用简洁中文解释关键设计约束）；按项目需要同步维护 `README.md`、使用指南与经实际运行验证的示例代码，中大型项目可用 Sphinx 或 MkDocs 在 CI 中自动构建发布。

## 6. 参考项目布局（多模块 Python）

单文件脚本仍按 [Python 规范](../languages/python.md) 使用 PEP 723 内联元数据；多模块 Python 应用可参考以下布局（工具链沿用 `mise` + `uv` + `ruff` + `mypy` + `pytest`）：

```text
project/
├── mise.toml             # 固定运行时版本、任务入口与 .env 加载
├── pyproject.toml        # 包元数据、依赖与 ruff/mypy/pytest 配置
├── uv.lock               # 锁定依赖版本
├── .env.example          # 环境变量占位模板（真实 .env 写入 .gitignore）
├── src/<package_name>/   # 核心业务包（领域模块、I/O 适配层、数据模型等）
├── tests/                # 单元测试、BDD 场景与回归测试
└── docs/                 # README 之外的架构设计、用户指南或 Sphinx/MkDocs 源文件
```
