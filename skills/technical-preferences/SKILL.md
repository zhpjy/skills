# 技术偏好

## 通用开发偏好

1. 按用户明确要求、仓库具体约定、本 skill 偏好的顺序决策。先检查项目文档、配置和 CI，沿用稳定的工具链。
2. 优先用 `mise` 管理运行时和 CLI 版本，用语言包管理器管理项目依赖。项目任务用 `mise run <task>`，一次性命令用 `mise exec -- ...`。
3. 本地私密值放在已被 Git 忽略的 `.env`，通过 `mise` 加载。共享模板只写占位符，CI 和生产使用平台 secret。源码、日志、异常和测试输出均须避免泄露凭据。
4. 重要步骤和非显然决策用简洁中文注释解释原因，尤其关注配置读取、输入与权限校验、外部调用、数据处理、副作用及异常清理。命令、路径、标识符和协议字段保留原文。
5. 新增 SQL 指标或派生字段时，在表达式旁注明字段名、计算条件、返回值或状态、必要的空值处理，确保别名、DDL 与注释一致。
6. 设计界面时，优先用布局表达层次，精简次级标签和说明。
7. 实现或审查结束前，核对仓库约定、环境入口、工具版本、依赖、输入输出、副作用、错误路径和私密配置。至少执行一条相关验证命令，优先通过 `mise` 运行。验证受阻时说明原因和未执行的命令。

## 日常偏好动作

此处持续收录用户日常喜欢使用的工作方式。按用户当前请求触发相应动作，不在每次技术任务中全部执行。

### 1. 实践对标

触发：用户说“做一下实践对标”，或希望了解别人如何解决同类问题、是否有更成熟或更简单的做法，以改进自己的方案。

执行步骤：

1. 理解现状：阅读相关实现或方案，明确它解决的问题、约束和已有取舍；区分已验证事实与推测。
2. 查找外部实践：优先查阅官方建议、成熟开源项目和真实案例，提供可访问的来源链接；区分规范要求、作者经验和实验结论。
3. 对照适用条件：比较外部做法与当前方案的收益、成本、复杂度和限制，说明哪些经验适用、哪些不值得引入；不因流行或功能更多就判定更好。
4. 给出结论：明确应保留的部分和值得改进的部分，按收益和实施成本排序，提出最小可行的改进及验证方式。证据不足时明确说明。

完成标准：结论关联当前实现与外部来源，说明建议的理由和适用边界。默认交付分析与建议；实际修改按用户已授权的范围执行，单独提出“实践对标”不代表要求改代码。

## 专项指南

按当前任务读取匹配的条目。语言以实际源码、构建配置和 CI 为准，涉及多种语言时读取并应用各自的规范，其余语言沿用通用偏好。

- 编写或审查 Python 时，读取 [Python 规范](languages/python.md)。
- 编写或审查 Java 时，读取 [Java 规范](languages/java.md)。
- 初始化或修改环境、补充缺失工具、配置环境变量或切换环境时，读取 [环境与工具配置](references/environment.md)。
- 设计或审查需要跨工具操作指南的 MCP 服务时，读取 [MCP 操作指南设计](references/mcp-guides.md)。
- 新增或实质改变模块边界、数据存储、权限隔离、对外接口、部署方式或关键依赖选型时，读取 [架构决策记录](references/adr.md)。
